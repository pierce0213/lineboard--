# 跨平台兼容性报告

> **结论：能在 Linux 上跑，Windows / macOS / 各种 Linux 发行版、桌面与触屏都一样。**
>
> 实测数据：12 个平台场景 × 2 套浏览器内核（Chrome、Edge），各 **278/278** 项断言全绿；
> 原有 149 项功能回归测试同样全绿。过程中发现并修复了 **7 个真实的跨平台问题**（含一个
> 手机端「画布只剩 140px」的可用性缺陷）。
>
> v1.0.0 起新增 4 项断言，每个场景都跑：版本徽章渲染、品牌标题行不溢出、
> 徽章不与右侧按钮相撞、标题行不越出面板（版本徽章加入后标题行一度溢出 5px，实测发现并修复）。

---

## 一、为什么这件事本质上「与操作系统无关」

这是一个**单文件 HTML**，约 4400 行，全部逻辑跑在浏览器里：

- 没有原生扩展、没有 npm 依赖、没有编译步骤
- 不读注册表、不写系统目录、不调用任何 shell
- 唯一的网络行为是 AI 生成（可关闭），其余全部在本机完成

所以「能不能跑」取决于**浏览器**，而不是操作系统——浏览器本身已经把系统差异抽象掉了。
真正与 OS 沾边的只剩四件事，全部在本次处理完毕：

| 与 OS 相关的点 | 影响 | 本次处理 |
|---|---|---|
| 系统字体不同 | Linux 缺中文字体时界面可能掉到衬线体 | 补齐字体链 |
| 表单控件默认样式 | Firefox 下滑块会退回系统默认蓝色 | 补 `-moz-` 规则 |
| 快捷键习惯 | Mac 是 ⌘ 不是 Ctrl | 文案按平台改写 |
| 窗口尺寸习惯 | 手机/小平板视口窄 | 窄屏自动收起面板 |

## 二、验证方法（以及这次**没能**真跑的部分）

先说清楚限制，避免误会：**本机是 Windows，WSL 被安全策略屏蔽，也没有 Docker，因此没有
真机 Linux 环境**。所以采用的是一条等价强度的替代路径：

**第 1 层 · 静态审计**
把源码里所有平台敏感 API 逐条挖出来，对照各引擎支持情况列表（见第三节矩阵）。

**第 2 层 · 平台特征模拟**
用 CDP 在**页面脚本执行之前**注入平台桩（`navigator.platform`、`userAgentData`、
触摸能力、`devicePixelRatio`、视口尺寸、存储可用性、老内核缺失的 API），
再加载应用跑同一份用例。共 12 个场景：

| 场景 | 模拟内容 |
|---|---|
| `win-chrome` | Windows · 1600×900 · DPR 1 |
| `win-hidpi` | Windows · 4K 缩放 · DPR 2 |
| `linux-chrome` | Linux · 1366×768（最常见的笔记本分辨率） |
| `linux-small` | Linux · 1024×640（老上网本） |
| `linux-firefox-ua` | Linux · Firefox 标识 |
| `macos-retina` | macOS · Safari 标识 · Retina DPR 2 |
| `macos-1280` | macOS · 1280×800 |
| `linux-privacy` | **任何 localStorage 访问都抛异常**（最严苛的隐私模式） |
| `linux-legacy` | 无 `ResizeObserver`、无 `structuredClone` 的老内核 |
| `android-touch` | Android · 412×915 · DPR 3 · 触屏 |
| `ipad-touch` | iPadOS · 820×1180 · DPR 2 · 触屏（⌘ 判定） |
| `file-protocol` | **双击 HTML 文件**走 `file://` 协议打开 |

每个场景约 19~22 项断言，覆盖：启动无报错、落笔出笔迹、存档、撤销/重做、快捷键文案、
数字键切换工具、多指防护、中断恢复、DPR 缩放、视口溢出、滚轮与右键拦截、触屏绘制。

**第 3 层 · 双内核交叉**
同一套用例分别在 Chrome 与 Edge 上完整跑一遍，排除「单一构建的偶发行为」。

### 这套方法覆盖不到的部分（诚实交代）

模拟的是**平台特征**，不是**真引擎**。以下三点需要在真机/真浏览器上复核：

1. **真机 Linux**（Ubuntu / Fedora / Debian + Chromium/Firefox）——验证字体回退的实际观感、无 GPU 环境下的 Canvas 性能
2. **Gecko（Firefox）真实渲染**——`-moz-` 样式是否如预期生效
3. **WebKit（Safari）真实渲染**——Safari 会忽略 `imageSmoothingQuality`（不影响功能，仅降采样质量略降）

## 三、平台兼容矩阵

| 能力 | 用途 | Chrome / Edge | Firefox | Safari | Linux 可用 |
|---|---|---|---|---|---|
| Canvas 2D | 全部绘制 | ✅ | ✅ | ✅ | ✅ |
| `PointerEvent`（`isPrimary` / `pointerType`） | 鼠标、触屏、手写笔 | ✅ 55+ | ✅ 59+ | ✅ 13+ | ✅ |
| `touch-action:none` | 触屏绘制不与页面手势打架 | ✅ | ✅ | ✅ | ✅ |
| `localStorage`（全部访问点带 try/catch） | 自动存档 | ✅ | ✅ | ✅ | ✅ |
| `ResizeObserver`（含 `window.resize` 兜底） | 画布自适应 | ✅ 64+ | ✅ 69+ | ✅ 13.1+ | ✅ |
| `FileReader` / `input[type=file]` / 拖放 | 参考图导入 | ✅ | ✅ | ✅ | ✅ |
| `paste` 事件 + `clipboardData.files` | ⌘/Ctrl+V 贴图 | ✅ | ✅ | ✅ | ✅ |
| `URL.createObjectURL` + `a[download]` | 导出 PNG / 工程文件 | ✅ | ✅ | ✅ | ✅ |
| `getImageData` | 图片转填格 | ✅ | ✅ | ✅ | ✅ |
| `WheelEvent` / `KeyboardEvent.code` | 缩放、跨布局快捷键 | ✅ | ✅ | ✅ | ✅ |
| `imageSmoothingQuality` | 降采样画质 | ✅ | ✅ | ⚠️ 忽略该属性，不报错 | ✅ |

**结论**：不存在「Linux 不支持」的项。唯一的三处差异都是**体验层面**且已处理：

- Firefox 不认 `::-webkit-scrollbar` / `::-webkit-slider-thumb` → 已补标准属性与 `-moz-` 规则
- Safari 忽略 `imageSmoothingQuality` → 退化为默认平滑，功能无影响
- 非 US 键盘布局（法语 AZERTY 等）数字键需要 Shift → 已同时按物理键位 `Digit1-9` 匹配

## 四、本次发现并修复的 7 个问题

| # | 问题 | 影响平台 | 修复 |
|---|---|---|---|
| 1 | 字体链只有 PingFang / 微软雅黑，**没有 Linux 中文字体** | Linux（中文显示会掉到无中文字形的字体） | 补 `Noto Sans CJK SC`、`Source Han Sans SC`、`WenQuanYi Micro Hei`、`Ubuntu`、`Cantarell`、`DejaVu Sans` |
| 2 | `::-webkit-slider-thumb` 缺少 Firefox 版本 | Firefox（滑块退回系统默认蓝色圆点） | 补 `::-moz-range-thumb` / `::-moz-range-track` |
| 3 | 面板滚动条只写了 `::-webkit-scrollbar` | Firefox（拖出一条默认滚动条） | 补 `scrollbar-width:thin` + `scrollbar-color` |
| 4 | 复选框只有 `appearance:none` | 老 Firefox（< 89） | 补 `-moz-appearance:none` |
| 5 | **快捷键文案写死 `Ctrl`**（功能层早已支持 ⌘，只是提示是错的） | macOS / iPadOS | 新增平台判定与 `localizeShortcuts()`，按平台重写 tooltip 与正文；运行期动态消息改用 `MOD` 常量 |
| 6 | 数字工具键只认 `e.key` | 任意非 US 布局（法语 AZERTY 数字需 Shift，1–9 完全没反应） | 同时匹配 `e.code` 的 `Digit1`–`Digit9` |
| 7 | **手机竖屏画布只剩 140px** | Android / 手机浏览器 | 窄屏（< 760px）默认把 272px 面板收起为 58px 图标栏；画布 140px → **354px（占视口 86%）** |

另外补了两项触屏健壮性（属于预防性加固，非现存 bug）：

- **多指防护**：`pointerdown` 增加 `isPrimary` 校验。此前平板上两指同时落下会各自起一条笔
- **中断恢复**：新增 `pointercancel` 监听。此前触屏上弹出系统通知或被手势接管时，笔会永远卡在「按下」状态

第 7 项是本次最有价值的发现——它不在任何静态审计能扫到的范围内，是**把视口缩到 412px 实际跑一遍**才暴露出来的。

## 五、已知差异（不影响功能，但用户会看到）

1. **字体渲染**：Linux 上中文走 Noto Sans CJK，字重与 macOS/Windows 略有差异，属正常现象
2. **滚动条**：Firefox 用的是标准细滚动条，与 Chromium 的圆角样式不完全一致
3. **触控板双指滚动 = 缩放**：应用统一接管 `wheel` 事件做缩放，Mac 触控板用户双指滑动会缩放而非滚动页面（这是画布类工具的通行做法，属设计选择）
4. **导出文件落到系统默认下载目录**：由浏览器决定，应用无法指定
5. **`file://` 协议下**：Chrome / Edge / Firefox 实测自动存档均正常（已纳入测试场景）；Safari 对 `file://` 的存储限制较严，如需长期存档建议用本地服务器或在线部署

## 六、建议的真机验证清单

如果你手上有其他环境，按这个顺序验最有价值：

1. **Ubuntu 24.04 + 系统自带 Firefox** —— 一次性覆盖「真 Linux + 真 Gecko + 中文字体」三个未验证项
2. **iPhone / Android 真机** —— 验证多指与系统手势打断的实际手感（模拟环境无法完全复现）
3. **无独立显卡的 Linux 服务器桌面** —— Canvas 在软件渲染下的流畅度

## 七、复现方式

```bash
# 跨平台兼容性（12 个场景）
node run-compat.mjs "<项目目录>" "compat-tests.js" \
     "C:/Program Files/Google/Chrome/Application/chrome.exe" "Chrome"

# 换 Edge 内核再跑一遍
node run-compat.mjs "<项目目录>" "compat-tests.js" \
     "C:/Program Files (x86)/Microsoft/Edge/Application/msedge.exe" "Edge"

# 功能回归（7 套）
node run.mjs "<项目目录>" "tests.js"
```

用例与 driver 位于 `%TEMP%/arc-e2e/`：`compat-tests.js`（用例）、`run-compat.mjs`（多平台 driver）。
driver 不依赖 puppeteer，只用 Node 22 自带的 WebSocket 直连 CDP。
